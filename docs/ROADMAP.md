# Roadmap

The roadmap describes outcomes, not deadlines. A phase closes only after its complete user journey is designed, implemented, tested, and reviewed.

## Phase 0 — Foundation

- Product, design, architecture, data, AI, and contribution documentation
- Feature-first code structure and shared design tokens
- Supabase server/browser clients and Vercel configuration
- Quality gates: strict TypeScript, lint, production build

## Phase 1 — Access and first trip

1. Passwordless authentication and protected journal
2. Create and edit a trip
3. Trip dashboard with a calm, contextual next action
4. Preparation, packing checklist, trip checklist, and trip details

## Phase 2 — Capture the journey

1. Trip days and daily journal
2. Moments with resilient draft saving
3. Photo upload, metadata, captions, and ordering
4. Places and map
5. Timeline and gallery

## Phase 3 — Meaning from memories

1. AI daily story with review and regeneration
2. Suggested highlights and photo organization
3. AI trip summary
4. Travel book preview, editing, and export

## Release standard

Accessibility, mobile use, privacy, loading and error states, analytics-free core behavior, and recovery from interrupted uploads are part of each feature—not later polish.

## Deferred

All non-travel modules remain architectural possibilities only. They receive no routes, UI, tables, or placeholder pages until Travel Journal is excellent.
